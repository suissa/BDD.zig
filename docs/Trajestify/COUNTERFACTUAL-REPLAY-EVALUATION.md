# Trajectory replay and counterfactual evaluation

The counterfactual evaluator compares a recorded divergent trajectory with a second execution of the same intent under a declared intervention.

## Run

Build Trajestify, then provide paired artifacts as JSON:

```sh
npm run evaluate:counterfactual -- --input=evaluation/replays.json
```

Each replay record contains:
- `replayId`: unique pair identifier.
- `baseline`: original divergent Trajestify artifact.
- `counterfactual`: replay artifact from the same trajectory, with a distinct run ID.
- `intervention`: an ID, target clause ID, and human-readable description.
- `confirmedHypothesisId` (optional): independently confirmed hypothesis used only to inspect its rank.

Both artifacts must include the intervention target clause. The baseline must contain a divergence. The evaluator reports whether the divergence was resolved, persisted at the same clause, or shifted to another clause. It also reports each run's ranked hypotheses and, when supplied, the confirmed hypothesis rank.

## Interpretation and safeguards

- Each artifact is ranked independently; the confirmed label is never supplied to the ranker.
- Replay pairs must belong to the same trajectory and use distinct run IDs.
- `resolved` means the counterfactual artifact contains no divergence. `persists` means its first divergence remains at the baseline clause. `shifted` means the first divergence moved to another clause.
- Rank changes are descriptive, not causal estimates. This harness does not claim the intervention caused a resolution; uncontrolled inputs, environment, state, and nondeterminism may explain differences.
- Use deterministic fixtures or capture all relevant external state when producing replay artifacts. Keep intervention design and ground-truth confirmation independent from rank generation.

This is an evaluation harness, not an automatic production replay engine. It consumes artifacts generated by `runTrajectory` and does not re-execute external side effects.
