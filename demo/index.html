Como usar o BDD.zig

Um mini-framework BDD em Zig que transforma um arquivo .feature em testes nativos, parseados em comptime e executados contra uma struct Zig. Cinco cenários, todos interativos.

testes.feature 
Feature: Transferência bancária

  Background:
    Given saldo = 100
    And limite = 50

  Rule: Transferência simples
    Scenario: Sacar 30
      When transferir(30)
      Then saldo == 70
main.zig 
// O arquivo vira parte do binário em compile-time
const feature = @embedFile("testes.feature");

// parseFeature roda em comptime → array de steps
const steps = comptime parseFeature(feature);

// Cada step roda contra sua struct
try runBDD(ContaBancaria, steps);
O ponto-chave: o arquivo .feature é embutido no binário e parseado em tempo de compilação. Erros de keyword, placeholders errados e steps quebrados viram @compileError — você descobre antes mesmo de rodar.

Para usar: 1) escreva seu meu.feature com Gherkin → 2) defina uma struct Zig com os mesmos campos e ações → 3) rode zig test main.zig.

Passe o mouse sobre cada card para entender a função. Aliases compartilham a mesma forma mas ganham nome diferente para legibilidade.

Keywords primárias (estrutura)

Feature
Obrigatória. Primeira linha do arquivo. Só uma por arquivo.
Rule
Escopo lógico. Reinicia o Background local da regra.
Background
Steps comuns que rodam antes de cada Scenario/Example.
Scenario
Sequência de Given/When/Then que testa um comportamento.
alias: Example
Scenario Outline
Template parametrizado. Expande uma execução por linha de Examples.
alias: Scenario Template
Examples
Tabela de dados que alimenta placeholders <como> este.
alias: Scenarios

Keywords semânticas (steps)

Given
Define o estado inicial. Aceita campo = valor e campo = valor and campo = valor.
forma: Given saldo = 100
When
Dispara uma ação. Aceita nome(valor) ou nome valor.
forma: When transferir(30)
Then
Verifica o resultado. Aceita campo == valor, campo expect valor ou error NomeDoErro.
forma: Then saldo == 70
And
Continua a keyword anterior (Given / When / Then).
But
Igual a And, mas semanticamente "ainda". Herda a keyword anterior.
*
Asterisco universal. Herda a última keyword semântica (Given/When/Then).
Três regras de ouro:
  1. Feature deve ser a primeira primária do arquivo.
  2. And, But e * precisam de um Given/When/Then antes — herdam o significado.
  3. Steps que não seguem os formatos viram Doc — documentação livre que não altera o estado.

Do texto Gherkin até a execução nativa, tudo passa por três etapas. A diferença crítica do framework: a primeira e a segunda rodam em comptime, antes do binário existir.

1
runtime · texto bruto
Seu arquivo .feature mora no disco. Você edita, versiona, revisa. Nada de especial.
testes.feature
2
comptime · embed + parse
@embedFile traz o texto para dentro do binário. comptime parseFeature() varre linhas, classifica keywords e constrói um []const Step.
compilação · falha rápido
3
runtime · executar
runBDD() percorre o array. Cada Given mexe em campo via @field. Cada When invoca a action via @call.
binary execution
Por que isso importa

Em frameworks BDD tradicionais (Cucumber, Gherkin puro), o parse acontece em runtime. Aqui, tudo que pode quebrar vira @compileError antes do binário existir:

  • Feature fora do topo
  • And/But/* sem G/W/T anterior
  • Scenario Outline sem Examples
  • <placeholder> sem coluna

E o melhor: @embedFile faz seu .feature viajar dentro do binário — sem leitura em runtime, sem caminho relativo, sem "funciona na minha máquina".
